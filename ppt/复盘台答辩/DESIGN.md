# 复盘台 · 7 分钟答辩 PPT 设计稿

## 全局约定

**画布**：1280×720；安全区上下 60px、左右 60px；内容区 1160×600。

**配色（金融深蓝，单一色板）**

| 槽位 | Hex | 用途 |
|---|---|---|
| 主色 | `#1E3A5F` | 封面/封底底色、左标题块、强调条 |
| 辅色 | `#64748B` | 分隔线、次要文字、表格线 |
| 强调 | `#B08D57` | 关键数字、核心标注（一页 ≤3 处） |
| 底色 | `#FFFFFF` | 内容页背景 |
| 浅底 | `#F4F6F9` | 结论条、表格容器底 |
| 正文 | `#1A1A1A` | 主文字 |

数据色例外：涉及 A 股涨跌时按国内习惯，涨 `#C5221F`、跌 `#0B7A45`，只用于数字。

**字体**：中文 微软雅黑；西文 Arial。巨型数字用 Arial Bold。
**字号阶梯**：封面主标 72 / 页面主标 34 / 卡片小标 22 / 正文 18 / 注释 14 / 巨型数字 96–110。

**视觉母题**：每页标题下 1px 贯通细线（`#D9DEE6`），右上角页码（y=670，14px，`#64748B`）。内容页复用，封面/封底不放。

**节奏**：10 页；Hero 3 页（P1 封面 / P8 逐笔 / P10 封底），其余 supporting；Hero 不相邻。

## 逐页

### P1 封面
- type: cover / role: hero / rhythm: peak
- layout: 大字报式，深蓝满版，左下角堆叠标题
- visual: L3 无；靠排版
- density: 字数约 60 / 图片 0 / 留白约 45%
- anti_pattern: 禁止在封面放任何指标数字；禁止页尾
- description: 小标「2026 黑客松 · A 股复盘工具」；主标「复盘台」72；副标「市场复盘 × 个人交易画像」；一行说明「收盘后你看到的是 5577 只票的涨跌，我们回答的是这些数字和你的账户有什么关系」；底部信息层「2026-11-05 · 答辩 7 分钟」。

### P2 问题：你看到的只有市场
- type: content / role: supporting / rhythm: valley
- layout: 左文右数（7:3，非对称）
- visual: 巨型数字 5,577（右侧，Arial Bold 110）
- density: 字数约 120 / 图片 0 / 留白约 25%
- anti_pattern: 禁止三张等宽卡片；禁止把 5,577 做成小字注脚
- description: 左侧列三行现象——「涨跌家数 4662 / 774」「成交额 20,495 亿」「涨停 124 家」；右侧巨型数字 5,577 与一句「今天有 5,577 只票在动」。底部结论条：「行情软件回答『市场怎么了』，没有一个字回答『你做得怎么样』」。

### P3 定位：把复盘拆成两半
- type: content / role: supporting / rhythm: valley
- layout: 对比式（左右两区，中间竖线 + ×），非等分 6:4
- visual: 无图，靠结构
- density: 字数约 220 / 图片 0 / 留白约 20%
- anti_pattern: 禁止 50:50 对分；禁止把两半都做成四项等大卡片
- description: 左「市场侧」——宽度/温度、板块归因、个股诊断、资金流；右「个人侧」——交割单还原含费成本、16 型交易人格、逐笔操作复盘、卖出后回看。底部结论：「市场数据是背景板，个人决策才是主角」。

### P4 现场演示：一个 HTML，三步
- type: content / role: supporting / rhythm: valley
- layout: 上图下文（截图占上 55%）
- visual: L2 `assets/hero.png`（内容区上方，宽 900）
- density: 字数约 140 / 图片 1 / 留白约 20%
- anti_pattern: 禁止写成操作手册式的步骤清单；禁止放手机/浏览器外壳装饰
- description: 三步流程链：① 打开 `docs/demo.html`，首屏给出 4 个数字与两个入口；② 点「看交易画像」，看 16 型、四维与决策卡；③ 点「看逐笔复盘」，看 11 手的 0-100 合理性。底部结论：「单文件、无后端，双击就能开；断网也能演示」。

### P5 画像：坐标 + 改法，不是标签
- type: content / role: supporting / rhythm: valley
- layout: 左图右文（6:4，非对称）
- visual: L1 `assets/profile.png`（左 58%），L2 `assets/advice.png`（右下小图）
- density: 字数约 200 / 图片 2 / 留白约 18%
- anti_pattern: 禁止把 16 型做成 16 个彩色标签墙；禁止只讲类型不讲改法
- description: 左侧放真实画像卡截图（SACD 采药人 + 四维坐标）。右侧三段——「怎么算的」：FIFO 配对 31 笔成交，四维各二选一；「算出了什么」：节奏慢、走独立、赚了就走、押得集中；「怎么改」：亏损单持有不超过 10 天，到期仍亏 5% 以上先减半。底部结论：「同一型的人打法相同，该改的地方也相同」。

### P6 逐笔：每手一个 0-100（Hero）
- type: content / role: hero / rhythm: peak
- layout: 巨型数字 + 洞察，右下嵌入截图
- visual: 巨型数字 50（中位合理性，110），L2 `assets/journal.png`（右下 560 宽）
- density: 字数约 160 / 图片 1 / 留白约 30%
- anti_pattern: 禁止把 11 行表格原样铺满；禁止用红绿表示合理性高低（会与涨跌色混淆）
- description: 中央巨型数字「50」= 今天 11 手的中位合理性。左侧两个分解：位置层（当日分位、量能、持有天数）25 分；时点层（成交前 30 分钟、距日内高点、相对均价）71 分。举西部矿业：拖了 22 天才卖，但卖在当日 100% 分位——「卖晚了」和「卖在好位置」同时成立。底部结论：「时点层只用成交前的分时，之后的走势不参与评分」。

### P7 卖后：三个基准分开算
- type: content / role: supporting / rhythm: valley
- layout: 左标题色块 + 右内容（m，左 30%）
- visual: L2 `assets/sellreview.png`（右区 640 宽）
- density: 字数约 180 / 图片 1 / 留白约 20%
- anti_pattern: 禁止只给一个「卖飞/躲过」结论；禁止把相对卖价写成相对成本
- description: 左块写三个基准：本笔（对成本）、卖后 3/5 日（对卖价）、若持有至今（对成本）。右侧截图举证华友钴业：−10.7% 卖出，5 日后 −0.2%，但相对成本仍 −11.1%——卖掉并没有回本。底部结论：「结果和决策质量分开算，才不会被一次反弹带偏」。

### P8 技术：5577 只、42 秒、一个文件
- type: content / role: supporting / rhythm: valley
- layout: 四个数字横排 + 下方数据链路（SVG 流程）
- visual: SVG 流程链（腾讯/新浪/东财/baostock → 本地计算 → 单文件 HTML）
- density: 字数约 190 / 图片 1 / 留白约 20%
- anti_pattern: 禁止堆技术栈 logo 墙；禁止写「高性能、可扩展」这类空话
- description: 四个数字：5,577 只覆盖、42 秒生成一份、1 个 HTML 文件、18 项离线自检。下方链路说明：行情多源交叉、指标全部本地计算、断网可开。底部结论：「数字由程序算，AI 只负责解释；解释里的每个数字都要能溯源校验」。

### P9 边界：明确不做什么
- type: content / role: supporting / rhythm: valley
- layout: 对比式（左「能」右「不能」），非等分 5:5 但视觉权重不同
- visual: 无图，两组数字支撑
- density: 字数约 200 / 图片 0 / 留白约 22%
- anti_pattern: 禁止把「不做什么」写成免责声明式的套话；禁止用「仅供参考」收尾
- description: 左「能做」：市场归因、持仓成本还原、16 型画像、逐笔时点评分。右「不做」：不预测涨跌（方向准确率 53.8%，基线 53.0%）、不给买卖建议、波动区间只当包络（覆盖 77–83%，R² 0.068）。底部结论：「把不确定的地方说清楚，比装作能预测更可信」。

### P10 封底
- type: ending / role: hero / rhythm: peak
- layout: 一句独白，深蓝满版
- visual: 无图
- density: 字数约 40 / 图片 0 / 留白约 60%
- anti_pattern: 禁止只写「谢谢」；禁止放页尾
- description: 主句「每一笔，都算得清」（60px）；下方一行「复盘台 · A 股市场复盘 × 个人交易画像」；底部小字 `github.com/www498/ashare-review` 与 `docs/demo.html`。
